# ReliefChain Technical Terminology

- **Blockchain:** An immutable, decentralized public ledger used in ReliefChain to anchor financial state transitions and secure resource provenance.
- **EVM:** The Ethereum Virtual Machine; the runtime environment where our Hardhat-compiled Solidity smart contracts execute.
- **Smart Contract:** Self-executing code deployed on the EVM that strictly enforces the rules of our disaster campaigns and escrow funds.
- **AccessControl:** An OpenZeppelin security standard used on-chain to restrict smart contract functions to specific whitelisted wallet roles.
- **Multisig:** A cryptographic mechanism requiring multiple authorized signers (e.g., 2-of-3) to approve a transaction before escrow funds are released.
- **Indexer:** An asynchronous backend service that listens for EVM events and deterministically reconciles them against the PostgreSQL operational database.
- **Transaction Hash:** A unique cryptographic identifier for a specific interaction submitted to the blockchain.
- **Log Index:** The sequential position of a specific event emitted within a single blockchain transaction, essential for distinguishing multiple events in a multicall.
- **CID (Content Identifier):** A unique, hash-based identifier used by IPFS to locate evidence files (mocked locally in this MVP).
- **SHA-256:** A cryptographic hashing algorithm used to convert uploaded binary evidence photos into a fixed-length string, proving the file was never tampered with.
- **JWT (JSON Web Token):** A cryptographically signed token used to securely transmit the user's identity and Web2 role across our Express API.
- **RBAC (Role-Based Access Control):** A Web2 security middleware that restricts API endpoints based on the authenticated user's role (e.g., preventing a Donor from creating a Disaster).
- **Idempotency:** A design principle ensuring that submitting the same API request multiple times (e.g., due to network retries) only results in a single database transaction.
- **Isolation Forest:** An unsupervised machine learning algorithm we use to identify statistical outliers in multidimensional distribution data.
- **Anomaly Score:** A metric generated by our AI model indicating how mathematically unusual a specific distribution event is compared to historical norms.
- **Proof-of-Impact:** Our attribution engine that mathematically links a specific fractional donation to a tangible, physical resource distribution.
- **Audit Log:** An append-only chronological database table tracing critical actions from user initiation to final blockchain verification.
